# EARLYWINE PRODUCTION EDITING CONTRACT

This repository is an active, authored production system. It is not a greenfield redesign.

## Production authority

Inspect the current deployed repository files before touching code. Current production is authoritative. Do not resurrect an older page, prototype, previous-assistant build, historical screenshot implementation, or deprecated design merely because it exists elsewhere.

Read this contract and `docs/WORK_PRIMER_PROMPT.md` completely before changing production code.

When a design preference conflicts with a locked identity asset, the locked asset wins.

Aggressively improve weak HTML, DOM composition, CSS, JavaScript, event handling, navigation, panels, cards, section layouts, section order, supporting visuals, animation, typography, responsive behavior, accessibility, molten-weld systems, fireworks, lower heroes, AEGIS/Explorers, and data presentation.

## The Weld

The Weld is not centrism, compromise for appearances, “both sides are equally correct,” or identity-politics framing.

Every party or camp may carry something true and still be fatally incomplete.

Strip the signal from the tribe. Preserve what survives pressure. Kill what fails, including the preferred answer. Then build the structure none of the incomplete parts could build alone.

Use “all parties” when appropriate rather than forcing every issue into a binary left/right frame.

## Design language

Use presidential systems architecture: futuristic but serious, premium and authored, evidence-forward, with molten seams and cinematic black, red, gold, green, and blue. Preserve strong mobile presentation, generous vertical rhythm, and distinct visual grammar between major sections.

Avoid generic political templates, generic SaaS dashboards, cartoon science fiction, uniform card spam, and simplification for implementation convenience.

## Top-hero fireworks

There are two separate behaviors:

1. Automatic: slow, sparse, atmospheric, and concentrated toward the outer sky.
2. Interactive: tapping or clicking an open hero area launches a visible shell from below to the selected coordinate and explodes at that target.

Do not add a fireworks control unless explicitly requested. Buttons and links must not trigger fireworks. Pause animation offscreen. Respect `prefers-reduced-motion`.

## AEGIS / Explorers

The obsolete visual implementation is not protected; its concepts are.

The presentation may be rebuilt around AEGIS Explorer, Citizen Road Builder, Pillar Explorer, Weld Explorer, White Papers, sensors/telemetry, maintenance, DTDFM utility corridor, AEGIS fiber vault, and drainage/environmental interface.

It should feel like a modern infrastructure laboratory, not a flat retro-game interface.

Preserve evidence/status caveats. Do not let visual polish imply engineering verification that the source does not claim.

## JavaScript contract

- Use `addEventListener`.
- Use event delegation for repeated or dynamic controls.
- Support keyboard and touch.
- Use `IntersectionObserver` and `ResizeObserver` where appropriate.
- Use `requestAnimationFrame` for visual animation.
- Make animation visibility-aware.
- Use `AbortController` for network requests where relevant.
- Avoid inline `onclick`.
- Avoid duplicated listener explosions.
- Avoid unnecessary global state.

## Completion gates

Before completing an edit:

- Verify all three locked paths are unchanged.
- Verify all three locked images render.
- Verify current routes.
- Verify mobile layout.
- Verify keyboard navigation.
- Verify touch interaction.
- Verify reduced-motion behavior.
- Verify no public evidence status was silently upgraded.
- Verify no older design was accidentally restored.

When an old build conflicts with current production, current production wins.

When presentation conflicts with evidence, the evidence state wins.
